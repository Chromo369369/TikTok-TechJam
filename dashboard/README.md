# TechJam Visualization Dashboard

A separate, static React reporting layer for the conversational-shopping project. It does not import or alter the agent, evaluator, configurations, benchmark logic, or model artifacts.

## Setup

Prerequisites: Node 20+ (developed on 24.12) and, for the session-trace page only, Python 3.10+ (developed on 3.14). Both the agent and the tracer use only the Python standard library — there is nothing to `pip install`.

From this directory:

```powershell
npm.cmd install      # once
npm.cmd run data     # writes public/dashboard-data.json
npm.cmd run trace    # writes public/trace-data.json  (needs the catalogue; ~3 min)
npm.cmd run dev      # http://localhost:5173
```

`npm.cmd run data` is required — the app will not render without it. `npm.cmd run trace` is optional; skip it and every page still works except **Session trace**, which then shows the command to generate its data.

For a production check use `npm.cmd run build` (it re-runs `data`, typechecks, and bundles into `dist/`), or `npm.cmd run typecheck` on its own.

### Where the catalogue has to be

`npm.cmd run trace` drives the real agent over the real 50,000-row catalogue, which is not in the repository. Either put it at `data/catalog.jsonl` (see the root README for the download), or point at a copy you already have:

```powershell
$env:TECHJAM_CATALOG = "D:\TechjamTest\data\catalog.jsonl"; npm.cmd run trace
```

The script fails immediately with that hint if it cannot find the file.

## Data normalization

`scripts/build-dashboard-data.mjs` reads `C:/Users/ian/Documents/Projects/techjam-conversational-search-private/experiments/summary.csv`, `notes/**/*.md`, and `diagnostics/**/*.json` when that archive is available. It also reads this repository's `experiments/**/*.md`, and writes the portable static snapshot `public/dashboard-data.json`.

Set `TECHJAM_EXPERIMENTS` to point to a different archive. If it is unavailable, the script succeeds with local notes and manually curated historical milestone records clearly marked `source: "curated historical milestone"`.

The application loads only these static JSON files in the browser; there is no backend. Rerun `npm.cmd run data` after adding experiment artifacts.

## Session trace page

`#/trace` replays the agent's own per-turn reasoning: the shopper message, the clues and phrases extracted from it, how far the evidence narrows the catalogue, the top of the ranking with the hidden target marked, the #1-to-#2 confidence gap, and what every question and list length was worth in simulation.

The data comes from the observer in `demo/trace_session.py`, which drives the same `Agent` class and the same simulated customer the evaluator uses and changes neither. `npm.cmd run trace` is a thin wrapper:

```powershell
python ..\demo\trace_session.py --session public_0068,public_0089 --export public\trace-data.json
```

Trace different sessions by editing that list, or by running the script directly. Sessions are replayed from the start of the run, so a later `sample_id` takes longer — the agent's session counter and its learned "will a shopper answer this?" tally both change the decision, and tracing in isolation would show a decision the scored run never made. `python demo/trace_session.py --find` lists sessions worth recording. See `demo/README.md`.

The two shipped sessions are chosen for contrast: `public_0068` publishes ten products on turn 1 with a #1-to-#2 gap of 12.98, `public_0089` publishes one with a gap of 0.67. Same agent, same turn, different confidence.
